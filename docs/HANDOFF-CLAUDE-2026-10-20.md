## 2. UX: 질문 → 근거 → 비교 → 행동

색상이나 카드 수만 바꾸지 말고 다음 두 핵심 동선을 설계한다.

### 리서치 동선

`로봇 검색 → 관련 종목과 연결 근거 → 보고서 인용/페이지 → 주가의 보고서 시점 표시 →
동일 주제의 다른 종목·반대 의견·목표가/등급 변경 비교`.

- 결과 첫 화면에 왜 관련 있는지, 보고서 수·기관 수·관측 기간을 표시한다.
- 기업의 주된 사업 노출, 부수적 사업, 단순 본문 언급을 구분한다. 주제 관련도와 투자 매력도를 혼동하지 않는다.
- 차트의 보고서 마커 선택이 해당 원문 근거를 열고, 보고서 선택이 차트 시점을 강조하도록 양방향 연결한다.
- 발간 이후 주가 움직임은 관측된 연관으로 표시한다. 보고서가 가격을 움직였다고 인과를 단정하지 않는다.
- 현재 관점과 해당 시점에 수집되어 있던 정보 관점을 명시한다. 과거 화면에 늦게 수집한 리포트를 노출하지 않는다.

### 계정 동선

`오늘 평가 → 무엇이 바뀌었나 → 내일 매수/매도/유지와 이유 → 예상 현금·비중 → 실행 기록`.

- 매매 없는 날도 이유를 제공한다. 원금 납입으로 늘어난 평가액과 투자 손익을 분리한다.
- shadcn Skill·기존 프리미티브·semantic tokens를 사용한다. 한국 시세 색은 상승 빨강/하락 파랑.
- 375px에서 핵심 비교가 가능하고 키보드 선택/Sheet 복귀/검색 링크 공유가 가능해야 한다.
- loading/empty/error/stale 상태를 실제 데이터 경계와 연결한다. 임의 수치로 빈 화면을 채우지 않는다.

## 4. REST/API 감사

출발 파일: `export_api_v2.py`, `src/lib/api-v2.ts`, `src/proxy.ts`,
`src/app/api/v2/[...path]/route.ts`, `next.config.ts`, `public/api/v2/openapi.json`, `docs/API.md`.

이 문서 작성 시 API v1/v2 Python 계약 검사와 Node HTTP 메서드 검사4개를 재실행해 통과했다.
이는 코드/산출물 계약 확인이며 배포 CDN 전체의 실제 네트워크 검증을 대신하지 않는다.

로컬 실제 HTTP도 추가 확인했다. `/api/v2/strategies` GET200 JSON, HEAD200 본문0,
OPTIONS204 본문0+Allow, POST405 problem JSON+Allow는 정상이다.
**발견한 수정 대상:** `/api/v2/no-such-handoff-resource` GET404 problem JSON에
`Cache-Control: public, max-age=300, stale-while-revalidate=86400`이 붙는다.
새로 만들어질 경로의 이전 404가 오래 남을 수 있다. `next.config.ts`의 광범위 캐시 규칙과
fallback 응답/프록시의 적용 순서를 조사하고 명시적인 오류 응답 캐시 정책을 실제 HTTP로 검증한다.
미래 날짜 스냅샷 404에는 더 긴 CDN 규칙이 적용될 가능성도 있으므로 별도로 확인한다.
404 캐싱 자체가 REST 위반이라는 뜻은 아니며, 생성될 리소스의 신선도 요구와 맞는지가 핵심이다.

- v2는 명사형 리소스·확장자 없는 URI를 기본으로 JSON 정적 파일에 rewrite한다.
  GET/HEAD, OPTIONS204, 쓰기405+Allow+problem JSON, 미존재404, CORS, 캐시,
  불변 revision hash·스냅샷·v1 deprecated 경로가 이미 구현되어 있다.
- `.json` 자체나 복수형 여부만으로 REST 준수/위반을 판정하지 않는다. 자원 정체성과 실제 HTTP 의미를 점검한다.
- 로컬 실제 HTTP와 배포 환경을 구분해 GET/HEAD 본문·상태, OPTIONS, 미지원 메서드,
  404 캐시, ETag/Last-Modified가 있다면 조건부 요청, 리디렉션과 쿼리 처리 등을 증거로 남긴다.
- OpenAPI 경로/예제/스키마와 실제 응답, Swagger Try it out을 대조한다.
- FastAPI 메타데이터와 `/research/*.json` 보조 계약도 API 목록에 넣고 문서/운영 경계를 분명히 한다.
- v1 파괴 변경 금지, schema_version와 Python/TS/OpenAPI/문서를 함께 갱신한다.

## 5. 보고서 본문·주제·종목 연결 검색

현재 `build_search_index.py`는 종목명/티커/파일명 위주의 `hay`만 만들고,
`command-palette.tsx`가 토큰 includes와 결과14개 제한으로 검색한다. 본문 의미 검색은 아직 없다.

- 실제 Silver Markdown에서 페이지/문단 근거를 추출하고 보고서/종목/기관/발간일/수집 최초시각/
  원문 위치/해시를 가진 검색 청크를 만든다. 원문이 없는 검색 근거를 만들어내지 않는다.
- 첫 단계는 한국어 키워드/동의어/종목 별칭과 전문 검색 랭킹으로 구현한다.
  임베딩은 필요성·품질/비용/갱신 조건을 확인한 뒤 추가한다. 외부 유료 호출을 기본 경로로 만들지 않는다.
- 로봇/로보틱스/협동로봇/휴머노이드/감속기/액추에이터 등은 검색어 확장 예시다.
