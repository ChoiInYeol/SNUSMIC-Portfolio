# 보고서 본문 검색 (`/search`)

주제 → 관련 종목 → 근거 문단/원문 줄 → 주가의 발간 시점으로 이어 찾는 정적 전문 검색이다.
작성기 `scripts/build_fulltext_index.py`, 클라이언트 엔진 `src/lib/report-search.ts`, 화면
`src/components/research/report-search.tsx`, 동의어 `data/silver/reference/search_synonyms.json`.

```bash
uv run python scripts/build_fulltext_index.py            # 색인 재생성 (약 1분, 바뀐 파일만 씀)
uv run python scripts/build_fulltext_index.py --check    # 커밋된 색인이 낡았으면 exit 1 (CI)
uv run python scripts/build_fulltext_index.py --query 로봇 # 웹과 같은 순위를 터미널에서 확인
uv run pytest tests/test_search_golden.py && node --test tests/report-search.test.cjs
```

## 데이터 흐름

| 입력 | 쓰임 |
|---|---|
| `data/silver/reports/markdown/**/*.md` (Silver) | 유일한 근거 원천. 문단·표 행을 정제(표 파이프·HTML 주석 제거)해 청크로 만든다 |
| `data/silver/reports/parsed.csv` (Silver) | 성과 기록이 없는 보고서(섹터·미채점)의 주 분석 대상·발간일 |
| `src/data/report-performance.json` (Gold) | 종목 페이지 존재 여부·표시명·modern/archive 구분 |
| `src/data/report-first-seen.json` (Gold) | 보고서별 최초 수집일(`first_seen`) — "그 시점 관점" 필터 |
| `search_synonyms.json` (Silver, 사람이 관리) | 검색어 확장 동의어·관련어, 종목 별칭 추가, 일반어 별칭 금지 목록 |

산출물 `public/research/fulltext/` (카탈로그 `serving.fulltext_index`):

| 파일 | 내용 | 크기 (2026-10-20) |
|---|---|---|
| `manifest.json` | 보고서 1,649건(학회·발간일·수집일·주 분석 종목·언급 관계 요약), 종목+별칭, 동의어, 순위 파라미터 | 654 KB (gzip 113 KB) |
| `terms/000..511.json` | 용어 → `"idf:게시목록"` (idf 소수 4자리 + 보고서별 tf 부분 1..31, base64 varint). 한 줄에 용어 하나 | 512개, 약 13 MB |
| `reports/{id}.json.gz` | 보고서 1건의 청크(문단 번호·줄 범위·내용 해시·본문)와 언급 종목(관계·신뢰도·근거 청크) | 1,649개, 합계 42.9 MB (중앙값 25 KB) |

- 용어: 한글 2음절 바이그램 + 소문자 라틴 단어. 형태소 분석기 없이 조사·복합어(`협동로봇`)·한 음절 오타를 견딘다.
  한 음절 검색어와 숫자는 색인하지 않는다(티커는 종목 별칭으로 해석).
- 순위: 보고서 단위 BM25(k1 1.2, b 0.75). 가중치 = idf × (k1+1) × (q/31)², q는 문서별 tf 포화값의 제곱근 양자화. 단어마다 변형(원어 1.0 · 동의어 0.7 · 관련어 0.4 · 이름 오타 보정 0.8) 중 최댓값,
  2단어 이하는 모든 단어, 그 이상은 1개까지 누락 허용. 검색어가 종목(이름·티커)이면 그 종목이 주 분석 대상인 보고서를 먼저 둔다.
  문단 순위는 브라우저가 해당 보고서 팩을 받아 매긴다(정확 일치 우선, 근사 일치는 표시).
- 관련 종목: 일치 보고서의 주 분석 대상 + 본문에서 이름이 나온 종목. 관계 가중 주 분석 1.0 · 공급망/고객 0.6 · 경쟁/비교 0.5 ·
  산업 0.45 · 단순 언급 0.15, 신뢰도 high 1.0/medium 0.8/low 0.6. 언급은 최고 점수의 20% 이상인 보고서에서만 세고,
  종목 점수는 기여를 큰 순으로 0.5배씩 감쇠해 합한다(큰 회사가 여기저기 스쳐 언급돼도 위로 올라오지 않게).
- 관계 분류: 언급 주변 문장(±60자)의 단서어 규칙(`고객사·납품·수주…` / `경쟁사·피어·비교기업…` / `산업·섹터·밸류체인…`).
  3회 이상 같은 단서면 high, 1회 이상 medium, 단서 없음은 단순 언급(low). 모델이 아니며 사람이 검증하지 않았다.
- 종목 별칭: 아카이브가 다룬 종목의 표시명·회사명(+US 회사명 접미사 제거) 중, 그 종목 자신의 보고서 본문에 실제로 나오고
  둘 이상의 종목에 겹치지 않는 것만 쓴다(776개). 2~3음절 한글 이름은 조사 앞에서만, 라틴 이름은 한글이 바로 붙으면 매칭하지 않는다.
  고정 테마주 목록은 없다 — "로봇 관련 종목"은 매번 본문 일치에서 계산된다.

## 갱신 안정성 (커밋 churn)

- 보고서 순서는 append-only다: 커밋된 manifest의 순서를 그대로 두고 새 보고서는 뒤에 붙는다(새 것끼리는 first_seen, 미상은 마지막).
  삭제된 보고서는 그 뒤 보고서의 번호만 당긴다.
- BM25 기준값(`params.basis`: 문서 수·평균 길이)은 문서 수가 5% 넘게 바뀔 때까지 고정한다. 게시 항목은 문서별 tf 부분만 담고
  idf는 용어 줄 앞에 두므로, 새 보고서는 해당 용어의 idf 숫자를 바꾸고 게시 1개를 덧붙일 뿐 기존 게시 바이트는 그대로다.
- 샤드는 한 줄에 용어 하나로 쓰고, 샤드마다 내용 버전(`manifest.shard_versions`)을 둬 내용이 같은 샤드는 바이트도 같다.
- 시뮬레이션(2026-10-20, 보고서 1건 추가): 기존 순서 유지, 샤드 469~477/512개 파일이 바뀌지만 바뀐 줄은 15.4만 줄 중
  약 3,000줄(새 보고서에 나온 용어), 기존 게시가 바뀐 줄 0, 새 내용 약 25 KB. 새 보고서의 용어가 해시로 거의 모든 샤드에 흩어지므로
  파일 수 자체는 줄지 않는다. 이전 방식(first_seen 미상이 맨 앞)은 모든 문서 번호를 밀어 15.4만 줄과 512개 샤드를 모두 다시 썼다.

## 근거 원칙

- 인용은 Silver 원문 줄의 정제본뿐이다. 청크마다 `[문단 번호, 시작 줄, 끝 줄, sha256 앞 16자, 본문]`, 팩마다 원문 파일 sha256을 담는다.
  `tests/test_search_golden.py`가 표본 보고서의 모든 청크 단어가 인용한 줄 범위에 실제로 있는지 확인한다.
- kordoc Markdown에는 페이지 경계가 없어 **페이지 번호는 기록하지 않는다**. 위치는 문단 번호와 줄 범위이며,
  "원문 위치 열기"는 GitHub `?plain=1#L시작-L끝`으로 연다. 페이지가 필요하면 `transcribe_pdfs.py`가 페이지 구분 주석을 남기도록
  바꾼 뒤 재전사해야 한다(현재 범위 밖).
- 3개 이상 보고서에 똑같이 나오는 청크(면책 고지 등)는 근거에서 뺀다(1,392개).
- 성과 채점 범위와 혼동하지 않도록 보고서마다 `채점 대상(modern) / 아카이브·채점 제외 / 미채점(섹터·파싱 실패)`을 표시한다.
- "그 시점에 수집된 것만"은 끝 연도 말까지 `first_seen`이 있는 보고서만 남긴다. 수집일 미상 183건(성과 기록 없는 보고서 포함)은 제외된다.
- 종목 차트 링크는 `/stocks/{slug}?report={id}&date={발간일}`. 차트가 그 마커를 ◆로 강조하고 앞 6개월~뒤 12개월을 보여 준다.
  다른 종목 보고서에서의 언급이면 발간일만 표시한다. 문구는 "관측된 연관"이며 인과를 주장하지 않는다.

## 정확도 (골든 질의, `tests/fixtures/search-golden.json`)

판정 기준은 순위와 무관하게 본문에서 정했다: 자기 보고서에 로봇 관련어가 100회 이상이면 relevant(10종목), 10회 이상이면 acceptable(13종목).

| 질의 | 결과 (2026-10-20) |
|---|---|
| `로봇` | 1위 로보티즈, recall@20 0.70 (10 중 7), precision@10 0.90 |
| `108490` | 로보티즈로 해석, 주 분석 보고서 4건이 먼저 |
| `로보틱스`, `humanoid` | 동의어로 로보티즈·레인보우로보틱스 상위 10위 내 |
| `로보티즈` | 주 분석 보고서가 단순 언급 보고서보다 모두 앞, 단순 언급 종목은 모두 로보티즈 아래 |
| `휴머노이두`(오타) | 바이그램 4개 중 3개 일치로 로보티즈 상위 3위 |
| `로보티스`(오타) | 편집거리 1로 로보티즈 보정 |
| `qwxzv 없는말` | 결과 없음 |

`로봇`에서 20위 밖으로 밀린 relevant는 ISRG(22위, 영문 보고서라 한글 `로봇` 빈도가 낮음), HD현대(29위), 한국피아이엠(31위)이다.
상위 10위 중 판정 집합 밖은 SAMG엔터(kr-419530) 1개다. 이 수치는 작은 판정 집합에 대한 것이며 전체 회수율을 뜻하지 않는다.
별칭은 아카이브가 다룬 종목뿐이라, 다루지 않은 상장사(예: 삼성전자)는 관련 종목으로 묶이지 않고 본문 검색만 된다.

## 비용과 한계

- 첫 검색 전송량(gzip 기준): manifest 113 KB + 용어 샤드 3~20개(`로봇` 303 KB) + 결과 1쪽의 팩 10개(약 250 KB).
  홈·다른 페이지 번들은 이 색인을 import하지 않는다(`/search`와 팔레트 링크만).
- 저장소 비용: 팩 42.9 MB는 보고서가 바뀔 때만 다시 쓰여 git churn이 작다. 용어 샤드 12.4 MB는 보고서가 추가되면 대부분 바뀐다.
- 정적 호스팅이라 질의별 서버 연산은 없다. 동의어·단서어 규칙은 사람이 관리하는 데이터라 범위 밖 표현은 놓친다.

## 다음 단계 제안 (구현하지 않음)

- **임베딩**: 골든 질의를 30개 이상으로 늘렸을 때 동의어 확장으로도 recall@20이 0.8 아래인 주제가 반복되거나,
  "수주 잔고 증가" 같은 서술형 질의 수요가 확인되면 검토한다. 로컬 다국어 소형 모델로 청크 임베딩을 빌드 시 1회 계산
  (16만 청크 × 384차원 int8 ≈ 64 MB)하면 정적 배포가 부담스러우므로, 그때는 아래 동적 API와 함께 도입한다. 외부 유료 호출은 기본 경로로 두지 않는다.
- **동적 검색 API** (`/api/v2/search?q=`): 서버리스 함수가 SQLite FTS5(빌드 시 Silver에서 생성, 읽기 전용)를 질의해
  현재 정적 계약과 같은 모양(관련 종목 그룹·보고서·근거 청크)을 돌려주면 클라이언트 전송량이 질의당 수십 KB로 줄고 팩 복제본이 필요 없다.
  필요한 결정: 호스팅(함수 번들 크기·콜드스타트), 색인 저장소, 캐시 키(q+필터 정규화), 레이트 리밋, `/api/v2` OpenAPI 계약과 버전 정책.
  REST 리소스로 공개할 경우 `rest` 담당 범위(export_api_v2·openapi·docs/API.md)에서 함께 설계한다.
