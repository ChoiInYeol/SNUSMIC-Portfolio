## P0 4 — 관점별 정리와 조치

### P0-A 백테스트 시점 정합성 — backend · database
- `scripts/backtest/strategies.py` `_regime_risk_on()`: 전일 종가·전일 200MA만 읽는다. T-(`run_parking_core_chandelier`)·U(`run_kospi_core_chandelier_scaleout`) 두 곳 적용. Q `_q_market_units`는 전일 기준으로 호출.
- 오라클: `tests/test_financial_oracles.py::test_parking_regime_gate_does_not_read_same_day_close`.
- **2026-10-20 완료**: 전체 재전사 후 공표 숫자를 재계산하고 헤드라인을 재선정했다.
  현재 `W_allweather_chandelier`; [재계산 기록](KORDOC-ROLLOUT-2026-10-20.md). 과거 불변 스냅샷은 보존한다.

### P0-B 전략 페이지 UX 회귀 — frontend · ui · ux
- 전역 wealth series(83개월, 16KB) 복구 → 프리렌더 HTML에 `KOSPI_value` 83개 확인.
- 캔들: 404=데이터 없음, 그 외 실패=오류 상태(실패 promise는 캐시하지 않음) + shadcn `Skeleton`/`Alert`/`Button` 재시도.
- 전략 상세: `role="status" aria-live="polite"` 로딩 안내, 실패 시 `Alert` + 재시도.
- `src/app/error.tsx`, `src/app/not-found.tsx` 추가. 내비: 375px에서 `⌘K` 숨김 + `flex-wrap`.
- Playwright 확인: 정상 로드 시 오류 0, 상세 500 → Alert 표시 → 키보드 Enter 재시도로 복구, 페이지 오류 0.

### P0-C 스키마 · REST API 계약 — schema · REST API
- `openapi.json`이 모든 게시 파일/필드를 문서화(`/signals/latest`, `/forward.json`, `/strategy-details/*`, `dsr`, `walkforward*`, `disclaimer_ko`, `slots`/`counts` 구조).
- `tests/test_api_contract.py`: 모든 게시 payload를 openapi 스키마로 검증, 미문서 필드는 실패.
- `src/lib/api-schemas.ts`: zod 스키마가 TS 타입의 원천. 상세 fetch는 `safeParse`, 별칭 라우트도 같은 스키마. `tests/api-schemas.test.cjs`가 게시 파일 전부를 zod로 검증.
- 작성기 버그: `b.get("entry_basis_date", 기본값)`은 값이 `None`이면 null을 낸다 → `or` fallback. 불변 스냅샷 3건 때문에 스펙은 nullable.
- 캐시: 날짜 스냅샷 `max-age=3600, s-maxage=31536000`, 해시 자산 `immutable`, manifest는 latest와 동일 TTL.

### P0-D 릴리스 게이트 — backend · CI
- `export_signals_api.py --check`: 아무것도 쓰지 않고, 커밋된 산출물이 커밋된 원천의 재export와 다르면 exit 1(`generated_at` 제외). `tests.yml`은 재생성 대신 이것을 실행. append-only 경로(날짜 스냅샷·해시 상세)는 존재만 확인한다 — 같은 `as_of`로 재실행해도 스냅샷은 최초 게시본으로 동결되므로 내용 비교는 오탐이 된다.
- 수집기 주석을 실제 동작(하나라도 실패 시 게시 중단)에 맞게 수정. 정책 완화는 #7(P1)로 남김.
- `refresh-daily.yml`·`refresh-reports.yml`: 봇 커밋 전에 `--check` + pytest + Node 계약 테스트 + `npm run build`. 일일 타임아웃 45→60분.
